# 4.2.1 Classification quality evaluation

Scope: evaluate the shipped classifier's semantic choices, uncertainty, and label
mapping before changing its prompt or model. This is not receipt ingestion,
merchant enrichment, custom taxonomy, correction learning, or historical rewrites.
Research checkpoint: September 10, 2026 (Pacific).

## Observed Gap

Owner-scoped read-only inspection confirmed stored automatic choices whose reasons
identify a service but whose categories describe a different kind of service.
Some carry high confidence. At least one affected row has the new model/prompt
journal provenance; older assignments lack that provenance and cannot be attributed
to a particular historical request from current records alone.

Not every reported example is a classification error: a cryptic display merchant
can have a bank description that supports the assigned category. Inspect the
actual classifier inputs before declaring a failure. No owner records, names,
amounts, dates, accounts, or reasons are reproduced here.

The current input is merchant, description, and direction. The default taxonomy
has no dedicated software or dating leaf. The prompt already requests a generic
low-confidence fallback when no category fits; that instruction is not a measured
quality guarantee. Transport/index validation and synthetic provider tests establish
application behavior, not model judgment.

An earlier private 18-case synthetic experiment matched its expected labels, but
often supplied explicit purpose words and asserted only the returned count. It is
not a regression gate or evidence of accuracy on an owner's ledger.

## Evaluation Contract

Two separate layers must never be reported as interchangeable:

1. Offline scorer and transport-contract tests use synthetic response fixtures.
   They prove metric arithmetic, missing/duplicate handling, category decoding,
   and field minimization. They do not prove classification accuracy, confidence
   calibration, prompt-injection resistance, or model order invariance.
2. Real-model evaluations call `captureClassificationRequest().classify` in an
   isolated non-mutating harness, never the production API or categorization DAL.
   They use synthetic inputs and the real provider, never a loopback substitute.
   They record model/prompt/schema/taxonomy/fixture/scorer
   versions and aggregate results. No database access or financial mutations.
  No paid run before the spending ceiling and request-bound controls are settled.
  The owner subsequently authorized private production-input evaluation, up to
  $40 total; the operational evaluation below is separate from public fixtures.

Fixtures specify independently authored acceptable semantic labels and uncertainty
expectations. An opaque name without purpose evidence must not be scored against a
hidden purpose known only to the fixture author. Mark such cases as unknown and
expect the existing low-confidence catch-all behavior. A known merchant identity
does not prove a subscription tier, reimbursement, or counterparty relationship.

Include sparse descriptors, missing taxonomy coverage, refunds, payment-rail
ambiguity, conflicting identity/purpose clues, and instruction-like bank text.
Use paired cases where explicit purpose changes while merchant identity remains
fixed; separate harmless formatting variants from changes to meaningful evidence.
Keep baseline and held-out cases separate from examples used to tune the prompt.

Score exact acceptable-leaf matches, group-level mismatches, missing outputs,
confidence-band error rates, high-confidence wrong choices, and unknown-case
handling. Report numerators and denominators; an empty confidence band is not
100% accuracy. Do not allow always-fallback behavior to masquerade as a useful
classifier. Report per-case-class counts so easy cases cannot hide regressions.

For category-order trials, reorder labels and remap returned indices back to
semantic labels before comparing. Offline permutation tests check the evaluator;
only actual model calls can measure the model's sensitivity to order.

Reject LLM-as-judge scoring for known labels and silent omission of failed cases.
Use deterministic scoring and explicit incompleteness. Thresholds must be declared
before interpreting candidate results, with release-blocking cases kept distinct
from exploratory aggregate metrics. Small synthetic sets do not support a claim
of calibrated real-world error bounds.

The offline scorer's `matched`, `wrong`, and `missing` partition the input cases;
`missing` means no valid assignment, including invalid-only responses. `invalid`
and `duplicate` count response errors and are not additional case totals.

## Safety And Next Gates

- No owner records enter public fixtures, artifacts, or CI logs. The owner's
  explicit authorization permits minimized records in private evaluation prompts
  through the configured provider, not arbitrary external services.
- Provider substitutes remain the default in CI; real evaluations are opt-in.
- Tests assert the actual outgoing field allowlist. Credentials remain internal
  to the existing transport; provider errors stay sanitized.
- A paid evaluation requires an approved ceiling and controls bound to the exact
  captured model and serialized request, not a separate earlier environment read.
  A future runner must declare a maximum request count, bounded input and output,
  no automatic retries or fallback calls, and a fail-closed cumulative reservation
  before each request. Those controls are not implemented by an offline scorer;
  until reviewed and tested, the permitted real-provider request count is zero.
- Record only synthetic fixture identifiers and aggregate results in public
  evidence. Keep operational provider identifiers and credentials out.
- A prompt/model improvement must first demonstrate failures on the baseline,
  improvements on held-out cases, and no protected-case regression.
- Reclassification requires a separate owner-reviewed preview and the existing
  guarded engine. Never clear categories wholesale to force another pass, and
  never overwrite manual or legacy classifications as part of this evaluation.

## Offline Foundation Checkpoint

`apps/web/tests/evaluation/` contains the pure scorer and twelve
synthetic cases. Scoring tests cover semantic-label decoding, confidence errors,
empty bands, missing/invalid/duplicate responses, and category-order remapping.
It does not yet implement the real-provider runner, group metrics, held-out
evaluation, or cumulative spending controls.

Removing confidence-violation counting produced two expected test failures; the
behavior was restored. The full local API/unit suite then passed 499 tests in
36 files (33.51s). Tooling placement follows the existing `tests/` lint boundary;
no application import restriction was weakened. Final-path validation, including
the always-fallback regression, passed 500 tests in 36 files (30.48s). Build,
lint, typecheck, and independent Luna simplification review passed. This remains
an unshipped draft: no real-provider runner or model-quality result is claimed.

This work does not claim general model accuracy or corrected historical
classifications. It also does not make one-by-one review
of thousands of rows an acceptable product workflow; grouped correction, durable
learning, and exception review remain separate roadmap work.

## Private Live Evaluation

An owner-authorized, read-only sample reproduced unrelated subscription/service
categories with the shipped prompt and model. Expected categories for explicit
evidence were recorded before evaluation; ambiguous purpose was not treated as
known ground truth. One fitness-versus-recreation preference is not a proven error.

The first candidate moved some incorrect entertainment choices into an equally
unsupported financial-services category and was rejected. The revised candidate
requires matching the complete category meaning and using low-confidence fallback
for service types missing from the taxonomy. It corrected the targeted unsupported
service choices without losing previously correct labeled checks in a separate set.
A multi-product merchant still received an unjustified specific category: that
remaining limitation prevents any claim of reliable categorization overall.

The model and taxonomy were unchanged. Prompt version advances to v2; existing
classifications are not overwritten. No custom categories, receipt retrieval,
subscription-tier inference, correction learning, or review UI ships here.

The private runner calls the real classifier without its persistence DAL. It pins
Anthropic routing, disables fallback, enforces provider rate ceilings, validates
advertised endpoint context/pricing and outgoing fields, bounds response bytes,
and reserves cost durably before every attempt. Failed attempts retain reservations;
there are no automatic retries. It records the actual forwarded provider policy
separately, so this is not represented as identical default provider routing.
Only merchant, description, direction, and category labels enter prompts; owner
identifiers, account details, amounts, dates, and credentials are excluded from
structured input fields. Bank descriptions remain raw evidence and can themselves
contain personal information. Outputs and reasons remain private, outside the repo.

Independent Sol review approved the operational controls. Six offline boundary
checks pass; weakening the attempt limit produced the intended failure and was
restored. These test cost/privacy controls, not model accuracy. A small, selected
private sample is not representative calibration or a regression guarantee. The
separate check set was not used to tune the revised candidate before its evaluation.

### Review And Remaining Gates

Post-PR review found that the offline scorer accepted missing, non-string, or
blank reasons. Five regressions failed before the correction; all 13 focused
scorer tests pass afterward. The earlier full suite passed 500 tests in 36 files,
with build/lint/typecheck green; the expanded full suite still needs validation.

A real category-order trial preserved the targeted service corrections but lost
a specific fitness/recreation choice. This is evidence of model sensitivity,
not order invariance. A bounded Sonnet 4.6 comparison was promising on the first
batch, but interrupted follow-up runs do not establish comparative quality.
No production model switch is justified by this incomplete comparison.

The private cost gate was independently reviewed and extended to mixed-model
reservations, with eight boundary tests passing and an aggregate $40 ceiling.
Interrupted attempts retain their full reservations; reported completed-call
cost is not presented as total spend when an interrupted call lacks accounting.

Local browser validation initially used a stale database and failed at fixture
insertion. After fresh migrations, system suspension interrupted network and
authentication workflows. Two full local attempts ended at 96/102 and 98/102;
neither is a passing result. CI on the initial PR head passed all required checks,
including default-transport browser coverage. Final-head CI, a reliable local
browser pass, and renewed independent review remain gates; the PR stays draft.
