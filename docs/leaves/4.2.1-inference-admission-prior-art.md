# 4.2.1 overlapping-inference correction — prior-art amendment

Survey date: 2026-09-10

Scope: correct the confirmed same-owner overlap in initial automatic
classification. Two requests could previously pay for two model calls for one
candidate; the existing NULL-category compare-and-set prevented only the
duplicate write. This amendment adds owner admission, a 90-second lease, fenced
completion, durable initial-run provenance, and manual revision advancement.

The researched source contracts remain
[`4.2.1-prior-art.md`](4.2.1-prior-art.md),
[`4.2.1-openrouter-prior-art.md`](4.2.1-openrouter-prior-art.md), and the shared
admission design in
[`4.2.4-reclassification-design.md`](4.2.4-reclassification-design.md).
This correction adopts their existing NULL-only candidate policy, least-data
prompt, validated structured response, fixed provider data controls, one
40-row request, short PostgreSQL transactions, partial unique owner admission,
lease recovery, and run-id/revision/timestamp compare-and-set fencing.
PostgreSQL's
[`clock_timestamp()` contract](https://www.postgresql.org/docs/16/functions-datetime.html)
supplies current wall-clock time rather than transaction-start time, while
[`SELECT ... FOR UPDATE`](https://www.postgresql.org/docs/16/sql-select.html)
supplies the owner-run row lock. Lease evaluation occurs in a separate query
after that lock is acquired so time spent blocked cannot authorize an expired
finalizer; the database regression coordinates a real blocked lock across the
deadline.

The bounded implementation records requested and actual model identity,
prompt/schema/provider/taxonomy fingerprints, counts, a result hash, and
sanitized nullable usage/generation metadata. It stores no prompt, completion,
description, merchant, amount, account, or provider body. Empty backlogs are
checked before admission so repeated page visits do not create journal rows.

Explicitly out of scope: a daily quota, public reclassification API,
operator proposal/apply/rollback, queue or cron, provider changes, and any
schema or migration change. Only the controlled operator workflow is sequenced
as subsequent 4.2.4 work; the other exclusions are not implicitly authorized.

## Execution record

The nine new real-PostgreSQL API tests passed before mutation testing (2.53s).
The full initial suite passed 405 tests in 32 files (26.43s).

Five deliberate source mutations produced the intended RED and were restored:
returning an active run instead of rejecting overlap; checking the lease before
waiting on its row lock; removing the exact payload timestamp guard; omitting
manual run clearing/revision advancement; and retaining `inferring` after a
provider failure. The lock mutation actually wrote one row after the lease
expired, while the restored code wrote none. The overlap fixture supplies a
valid second provider response, so the denial regression fails on an actual
200 response instead of depending on an unprimed substitute error.

These runs used synthetic ledger records and the loopback model transport only.
No production classifications or provider settings changed. Final full-suite,
browser, independent-review, and PR CI gates remain pending.
