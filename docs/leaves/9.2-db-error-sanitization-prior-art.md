# 9.2 database error sanitization correction

This is a narrow security correction discovered during the browser-test audit. It does not complete
leaf 9.2. A failed owned database write reached the Next.js server logger as Drizzle's full SQL,
parameter array, and PostgreSQL failing-row detail. Those fields can contain merchant text, amounts,
account identifiers, and user identifiers.

## Prior art

1. Cash Lens `CLAUDE.md` makes log minimization binding for financial data and requires real-boundary
   tests rather than owned-code mocks.
2. Cash Lens `lib/log.ts` already limits application events to identifiers, counts, and error classes;
   the leak bypassed that allowlisted logger through an uncaught framework exception.
3. Cash Lens `lib/plaid/client.ts` already translates a third-party error at its ownership boundary
   because the raw SDK error can retain secrets in request configuration.
4. Drizzle ORM 0.45.2 `errors.js` constructs `DrizzleQueryError` with the full query and parameters and
   retains both as public fields together with the driver cause.
5. Drizzle's node-postgres transaction implementation executes `BEGIN`, `COMMIT`, and `ROLLBACK`
   through the same query wrapper, and its prepared-query path wraps every rejected query in
   `DrizzleQueryError`, including client errors that are not PostgreSQL `DatabaseError` instances.
6. node-postgres 8.23.0 `client.js` creates a plain `Error("Query read timeout")` when its client-side
   query budget expires; `connection-parameters.js` applies URL fields after explicit pool config.
7. [PostgreSQL error fields](https://www.postgresql.org/docs/17/protocol-error-fields.html) separate
   stable SQLSTATE and constraint-name fields from human messages, detail, context, and internal query.
8. [PostgreSQL error codes](https://www.postgresql.org/docs/17/errcodes-appendix.html) recommends
   testing SQLSTATE rather than localized message text; class 23 exposes constraint names separately.
9. [Node.js errors](https://nodejs.org/api/errors.html) documents stable programmatic `code` fields and
   warns that human-readable messages can change.
10. [Node.js error causes](https://nodejs.org/download/release/v19.6.1/docs/api/errors.html#errorcause)
   shows that `util.inspect()` recursively renders `cause`, so wrapping the raw driver error as a cause
   does not redact it.
11. The [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
    says sensitive personal, account, and higher-classification data should be removed or sanitized.
12. [CWE-532](https://cwe.mitre.org/data/definitions/532) identifies sensitive information in logs as
    a confidentiality weakness and recommends not writing it.
13. [NIST SP 800-92](https://csrc.nist.gov/pubs/sp/800/92/final) treats inadvertent sensitive-data
    disclosure as a log-management risk.
14. [Next.js error handling](https://nextjs.org/learn/dashboard-app/error-handling) distinguishes the
    client fallback from uncaught server exceptions; a generic `error.tsx` does not sanitize server logs.

## Decision

Translate database failures at the two existing transaction ownership boundaries:
`withRequestScope` and `withPlaidItemScope`. The replacement error has a constant message and a fresh
metadata-only cause containing a validated five-character SQLSTATE and only the two constraint names
consumed by existing domain mappings. It
does not retain the query, parameters, PostgreSQL message/detail, or original cause. Exceptions created
by owned domain logic pass through by identity.

This keeps the two existing deterministic decisions: an obligation whose account disappears maps
`23503` plus `scheduled_obligations_account_user_fk` to `account_not_found`, and a duplicate Plaid item
maps `23505` plus `connections_user_provider_item_key` to `already_connected`. Broader observability,
log retention, and log transport policy remain leaf 9.2 work.
