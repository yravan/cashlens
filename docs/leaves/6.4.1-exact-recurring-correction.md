# 6.4.1 Exact Recurring Money

Scope: repair derived monetary precision in recurring detection and its existing
annual/upcoming consumers. Depends on PR105's exact formatter. No input-cap,
schema, cadence, eligibility, ownership, or provider change. Calendar-year
guards, action-error feedback, and layout corrections remain separate PRs.

## Prior art

The checked-in surveys `6.4.1-prior-art.md`, `6.4.2-prior-art.md`, and
`6.4.3-prior-art.md` remain the product basis. This correction preserves their
median, rational acceptance/stability bands, currency separation, annual cycle
counts, cancellation, staleness, and non-netted projection semantics. The
additional technical survey below was checked September19,2026.

| Source | Adopted or rejected |
| --- | --- |
| [ECMAScript BigInt division](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-bigint-divide) | Integer division truncates toward zero, preserving the existing even-median contract without an overflowing addition. |
| [MDN BigInt](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt) | Keep all derived arithmetic homogeneous; convert validated row numbers once before summing. No floating-point percentage arithmetic. |
| [MDN Array.sort](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort) | Comparators return number signs; compare BigInts relationally instead of returning their difference. |
| [MDN Intl formatting](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/format) | Reuse PR105's exact decimal-string formatter, not Number conversion at display time. |
| [React client boundary](https://react.dev/reference/rsc/use-client) | BigInt is supported in RSC props. Keep StreamActions' existing explicit JSON identity fields, which contain no money. |
| [MDN JSON limitation](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Errors/BigInt_not_serializable) | The upcoming overlap key serializes the absolute amount as a decimal string. Do not globally patch BigInt serialization. |
| [TypeScript target](https://www.typescriptlang.org/tsconfig/target.html) | Preserve the repository compiler target. |
| [TypeScript BigInt support](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-2.html#bigint) | Follow existing `BigInt(...)` constructor syntax; runtime support is already required by the money parser. No polyfill dependency. |
| [PostgreSQL aggregates](https://www.postgresql.org/docs/16/functions-aggregate.html) | Exact persisted values do not justify narrowing application aggregates to Number; PR105 addresses the SQL rollups separately. |
| [Drizzle runtime mappings](https://orm.drizzle.team/docs/sql#sqlmapwith) | Preserve safe individual row mappings; no broad schema codec migration is needed for this correction. |

Rejected: lowering valid input limits, clipping totals, fixing only formatting,
decimal floating-point percentages, converting derived values back to Number,
or changing the rounding policy. Native BigInt supplies the required integer
operations without a new dependency or a general money abstraction.

## Implementation

Same-day sums, typical/last amounts, exact rational cross-products, annual
multiplication/totals, and upcoming occurrence/totals use BigInt. Individual
transaction and obligation inputs remain safe numbers. Median sorting uses a
number-valued comparison; even medians divide by BigInt(2). The obligation
projection converts before negation. The overlap key retains exact magnitude.
Zero-deposit UI checks compare with BigInt(0), avoiding a spurious Expected in
section after the type migration.

Existing seed/test monetary expectations change representation only; stored
fixtures, amount magnitudes, dates, and product assertions are unchanged.
