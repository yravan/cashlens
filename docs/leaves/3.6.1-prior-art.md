# 3.6.1 Transaction History Page — Prior Art

Survey date: 2026-09-01

Scope: refinements inside the approved design envelope (docs/leaves/3.6.1-transaction-history-design.md — scope, DAL contract, closed URL schema, semantics, states, and security are already decided there). This survey settles the remaining UX and implementation details: filter-form interaction shape, URL-state conventions, pagination and result-announcement accessibility, amount-filter ergonomics, and literal-search safety.

## Sources and decisions

Empty controls submit as empty strings, so the parser treats `""` as absent (rejecting it would break every native form); applying filters drops `page` because the form carries no page input. |
| 13 | [National Bank of Belgium REST guide: out-of-range pagination](https://github.com/NationalBankBelgium/REST-API-Design-Guide/wiki/Pagination-Out-of-range-bounds) | A page past the end is a valid query with zero items: 200, empty list, real metadata — never an error, never a silent clamp. | Adopt: a well-formed `page` beyond `pageCount` renders the no-match state with true `total`/`pageCount` and intact controls. Only malformed values (`page=0`, `page=x`) are invalid queries. |
| 14 | [PostgreSQL: pattern matching](https://www.postgresql.org/docs/16/functions-matching.html) + [Jose Selvi: LIKE wildcard injection](https://www.pentester.es/like-sqli/) + [Monstarlab: SQL wildcard escaping](https://engineering.monstar-lab.com/en/post/2023/04/06/SQL-wildcard-operators-and-how-to-escape-them/) | `%`/`_` inside a bound ILIKE parameter still act as wildcards: over-matching, enumeration, and pathological patterns survive parameterization; escape backslash first, then both wildcards. | Adopt: the pattern builder escapes `\`, `%`, `_` in `q` before wrapping in `%…%`, so search is literal even against wildcard input. The 100-char cap bounds pattern cost. No trigram index until profiling demands one (design). |
| 15 | [Next.js 16 `page.js` reference](apps/web/node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/page.md) (pinned local docs) | `searchParams` is a Promise resolving to `string \| string[] \| undefined` per key — a repeated parameter arrives as an array; reading it opts the page into request-time rendering. | Adopt: the parser takes that exact record shape; `string[]` for any key is the design's "repeated scalar" rejection. The page is dynamic by nature — no caching decisions to make. |

## Distilled refinements (inside the design envelope)

1. **One native GET form, batch Apply** (#7, #8, #12): no client JS for filtering; Apply submits, Clear links to `/transactions`, applied values re-render in the controls, and every applied search is one history entry — back-button and shareability fall out of the platform.
2. **Empty means absent; page resets on Apply** (#12, #15): `""` params are dropped before validation; repeated params and unknown keys reject; the form carries no `page` field so a new search always starts at page 1.
3. **Absolute-magnitude amounts** (#2, #4): confirmed against three products' operator sets; `min`/`max` compare `abs(amount_minor)` within the mandatory `currency`.
4. **Filter-preserving pagination as a tested invariant** (#5, #9): prev/next links rebuild the full query string; `nav` landmark + `rel` links; out-of-range pages are valid empty results with honest metadata (#13).
5. **Announced states** (#10, #11): count line, no-match, and invalid-query messages are `role="status"`/text — no meaning in color alone (design).
6. **Literal search hardened** (#14): escape `\%_` inside the bound parameter; length-capped; case-insensitivity via ILIKE, not regex.
