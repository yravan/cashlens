# 4.2.1 amendment: OpenRouter transport — Prior Art

Survey date: 2026-09-09

Scope: founder-directed amendment to leaf 4.2.1 — swap the classification transport from the
Anthropic SDK to OpenRouter so the model is a one-var choice (`LLM_MODEL`). Surveyed: OpenRouter's
API surface and SDK story (can the Anthropic SDK target it at all?), structured-output support and
its per-endpoint variance, provider routing and data controls (the security story), error and
rate-limit semantics, and the model/pricing landscape for cheap classification. The original
4.2.1 survey (`4.2.1-prior-art.md`) still governs everything non-transport: prompt shape,
validation, provenance, triggers, batching.

## Sources and decisions

| # | Source | Evidence | Cash Lens decision |
|---:|---|---|---|
| 1 | [OpenRouter quickstart](https://openrouter.ai/docs/quickstart) | One endpoint: `POST https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer <key>` — an OpenAI-schema API; the OpenAI SDK works via `baseURL` override. No Anthropic-native `/v1/messages` endpoint exists anywhere in the docs. Attribution headers (`HTTP-Referer`, `X-OpenRouter-Title`) are optional, leaderboard-only. | The Anthropic SDK cannot target OpenRouter — the transport must speak OpenAI chat/completions. Skip attribution headers: they only publicize the app on rankings. |
| 2 | [OpenRouter SDKs](https://openrouter.ai/docs/sdks) | Official SDKs: `@openrouter/sdk` (TS), `openrouter` (Python), Go — thin autogenerated wrappers; plus an Agent SDK. No Anthropic-SDK compatibility. | Reject all SDK dependencies. The need is one non-streaming JSON POST with static headers; platform `fetch` + `AbortSignal.timeout` covers it in ~40 lines, and a new dependency is a security decision this doesn't justify. `@anthropic-ai/sdk` is removed. |
| 3 | [Structured outputs](https://openrouter.ai/docs/features/structured-outputs) | `response_format: {type:"json_schema", json_schema:{name, strict, schema}}`. Support is **per endpoint, not per model**; unsupported models error; `strict:true` triggers native enforcement where available but "exact compliance is not guaranteed on every endpoint". Their own recipe for forcing conformant routing: check the model's supported parameters, set `require_parameters: true`, send `response_format`. | Adopt `response_format.json_schema` with `strict: true` around the unchanged `ASSIGNMENT_SCHEMA`, plus `require_parameters: true` (#4) so requests only route to endpoints that honor it. Server-side allowlist validation stays the real safety net (unchanged from 4.2.1 #17): strict mode is a hint on some endpoints. |
| 4 | [Provider routing](https://openrouter.ai/docs/features/provider-routing) | `provider` preferences: `data_collection: "deny"` ("use only providers which do not collect user data" — default `allow` permits providers that "store user data non-transiently and may train on it"), `zdr: true` (ZDR endpoints only; logical OR with the account-wide setting), `require_parameters`, `order`/`only`/`ignore`, `allow_fallbacks`, `sort`. | Pin `provider: { data_collection: "deny", require_parameters: true }` on every request — routing can then never select a training/collecting endpoint, regardless of which model `LLM_MODEL` names. Reject pinning `zdr: true` in code: it would 503 many models the founder may pick (breaking the amendment's whole point); it is documented in production.md as the stricter account-wide/env choice, and the default model already routes to zero-retention endpoints under `deny` (#10). |
| 5 | [Privacy & logging](https://openrouter.ai/docs/features/privacy-and-logging) | OpenRouter classifies endpoints by training and retention; retention labels are display-only ("no routing rules that change based on data retention"), training/collection is what routing filters. Account-wide toggles: block training providers, ZDR-only. Enterprise regional routing exists. | The pinned `data_collection: "deny"` (#4) is the request-level enforcement; production.md points the founder at the account-wide "block training providers" and ZDR toggles as belt-and-suspenders. Retention worst case stays what 4.2.1 already accepted (#10). |
| 6 | [Errors](https://openrouter.ai/docs/api-reference/errors) | Error body `{error: {code, message, metadata}}`; HTTP status matches `error.code` pre-response. **A provider failure after headers yields `200` with an error body and no usable choices** — "check the body for an `error` field even on a `200`". 400 params, 401 bad key, 402 no credits, 403 moderation/guardrail (metadata carries the *flagged input excerpt*), 408 timeout, 429 rate limit, 502 provider down/bad response, 503 no provider satisfies routing. | Map by status **and** by embedded `error.code` on 200s: 401/402/403(key-disabled cases are 401; 402 is billing) → the founder-actionable `LlmUnconfiguredError` (401, 402); 429 → `LlmRateLimitedError`; 400/403/408/5xx/network → `LlmUnavailableError`. Never propagate or log `error.message`/`metadata` — moderation metadata embeds user transaction text, exactly what the sanitized-classes invariant exists to keep out of logs. |
| 7 | [Limits](https://openrouter.ai/docs/api-reference/limits) | Paid models have no platform request cap — 429s come from upstream capacity; `Retry-After` present only when every attempted provider hinted one. 402 = out of credits (negative balance blocks even free models); per-key credit caps via `GET /api/v1/key`. | Keep the route's fixed `Retry-After: 30` (client backoff contract unchanged) — the provider header is unreliable. Map 402 → `LlmUnconfiguredError` → 503: retrying cannot help, topping up is a founder act, and 503 is the existing "dormant until the founder acts" signal. |
| 8 | [Chat completion API reference](https://openrouter.ai/docs/api-reference/chat-completion) | Response: `choices[].message.content` (string, array of items, or null), `finish_reason`, `usage`. Tolerate string-or-array content. Same token budget and `temperature: 0` as before. |
| 9 | [API reference overview](https://openrouter.ai/docs/api-reference/overview) | `finish_reason` is normalized to exactly `stop`/`length`/`content_filter`/`tool_calls`/`error` (raw value in `native_finish_reason`); errors can also arrive inside a choice with `finish_reason: "error"`. | `finish_reason !== "stop"` → `InvalidClassificationError` (the 4.2.1 `stop_reason !== "end_turn"` check, one vocabulary over every model). ## Distilled design (what this amendment builds)

1. **Transport** (#1, #2): `lib/llm/client.ts` speaks OpenAI chat/completions to
   `${OPENROUTER_BASE_URL ?? "https://openrouter.ai/api/v1"}/chat/completions` with platform
   `fetch`, `Authorization: Bearer $OPENROUTER_API_KEY`, 30s `AbortSignal.timeout`, zero new
   dependencies; `@anthropic-ai/sdk` is removed. `classify.ts` (prompt, schema, validation) is
   untouched.
2. **Model choice** (#11): `LLM_MODEL` env, lazy, default `anthropic/claude-haiku-4.5` — the same
   model as before, now switchable without code.
3. **Data controls pinned in code** (#4, #5, #10): every request carries
   `provider: { data_collection: "deny", require_parameters: true }`. Not configurable — this is
   the security floor of using a routing intermediary.
4. **Structured output, portably** (#3, #10): `response_format.json_schema` (`strict: true`,
   unchanged `ASSIGNMENT_SCHEMA`); `require_parameters` routes only to enforcing endpoints and
   fails closed (503 → 502) on models with none, instead of silently degrading to free text.
   `parseAssignments` remains the authority regardless.
5. **Errors** (#6, #7, #9): one status/code map — 401, 402 → `LlmUnconfiguredError` (503);
   429 → `LlmRateLimitedError` (429 + fixed Retry-After 30); everything else, network failures,
   200-with-error bodies, and malformed envelopes → `LlmUnavailableError` or
   `InvalidClassificationError` (both 502). Provider `message`/`metadata` never leave `lib/llm`
   (moderation metadata quotes user input).
6. **Substitutes at the real seam** (#1): with no SDK module to alias, both suites substitute the
   HTTP boundary — the api harness becomes a loopback chat/completions server
   (`tests/harness/openrouter.ts`) wired via `OPENROUTER_BASE_URL`, e2e's `llm-stub.ts` answers
   the same shape. Zero secrets, nothing leaves the machine, and the production fetch path is
   exercised end to end (statuses, headers, bodies) instead of a substituted module.
