# 10.3 Test-log redaction

Scope: prevent Clerk testing and other E2E child-process secrets from reaching
live CI stdout or stderr. Artifact scrubbing remains in place. This change does
not alter application behavior, authentication, test assertions, or provider
requests.

## Observed leak

`@clerk/testing@2.2.22` installs a Playwright route handler that appends the
testing token to the FAPI URL. On a terminal FAPI failure it writes
`e.request().url()` to `console.warn`; the network-error path writes the same
URL to `console.warn` and may also call `console.error`. The status path appends
response headers and up to 500 characters of response body. Playwright forwards
those messages to the runner process, while `e2e/scrub-secrets.ts` only rewrites
files after the run. A public CI log can therefore contain a live dev-browser
or testing token even when uploaded artifacts are clean.

## Prior art and constraints

- [`child_process.spawn`](https://nodejs.org/api/child_process.html) provides
  separate pipes, `error`, `close`, exit-code, and signal events without a
  shell; this is the wrapper's process boundary.
- [`node:stream`](https://nodejs.org/api/stream.html) `Transform` streams and
  `pipeline` backpressure are the standard bounded way to transform child
  output while it is flowing.
- [`node:string_decoder`](https://nodejs.org/api/string_decoder.html)
  preserves a multi-byte UTF-8 character split across Buffer chunks, which is
  required before line-oriented matching.
- Node's [signal events and `process.kill`](https://nodejs.org/api/process.html#signal-events)
  document that installing a `SIGINT`/`SIGTERM` listener removes the default
  exit behavior; the wrapper therefore forwards cancellation to the child and
  re-emits a child signal only after output drains.
- Next's [environment-variable loader](https://nextjs.org/docs/pages/guides/environment-variables#loading-environment-variables-with-nextenv)
  explicitly supports `@next/env` outside the Next runtime. The wrapper uses
  the same development-mode load as `playwright.config.ts` before harvesting
  values from `.env*` files.
- Playwright's [`test` CLI](https://playwright.dev/docs/test-cli) defines the
  existing command, reporter selection, and exit-oriented options; the wrapper
  keeps the command and arguments observable rather than replacing the runner.
- Playwright's [reporter API](https://playwright.dev/docs/api/class-reporter)
  receives worker `stdout` and `stderr` chunks, including output outside a
  test, so sanitizing only assertion text or only artifacts is insufficient.
- Playwright's [global setup/teardown guidance](https://playwright.dev/docs/test-global-setup-teardown)
  documents the separate setup process and artifact lifecycle used by this
  repository; live process output still needs protection before teardown.
- The [WHATWG Streams standard](https://streams.spec.whatwg.org/) defines
  reader cancellation and pull-stream backpressure, matching the wrapper's
  child-pipe and bounded-carry design.
- The [WHATWG Fetch standard](https://fetch.spec.whatwg.org/) defines the
  one-shot body stream contract that applies to the browser-facing test and
  server-side route seams involved here.
- GitHub's [workflow command documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands#masking-a-value-in-a-log)
  documents `add-mask`, but masking must happen before output and is exact-value
  based; it cannot reliably cover a provider-generated URL emitted by a child
  before the workflow can register it.
- GitHub's [secrets reference](https://docs.github.com/en/actions/reference/security/secrets)
  lists automatic redaction limits and warns that structured secret values are
  difficult to match, supporting a repository-side sanitizer for token shapes.
- GitHub's [secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use)
  requires masking non-GitHub sensitive values and auditing stdout/stderr paths;
  public workflow logs and artifacts are distinct exposure surfaces.
- Clerk's [Playwright testing guide](https://clerk.com/docs/guides/development/testing/playwright/overview)
  documents `clerkSetup()` and `setupClerkTestingToken()`, including the
  development-instance Testing Token flow that produced this incident.
- The pinned local source at
  `apps/web/node_modules/@clerk/testing/dist/chunk-6QEJXXZK.mjs` from
  `@clerk/testing@2.2.22` is the concrete producer: its Playwright route adds
  the testing token to the FAPI URL and its terminal retry paths print the URL,
  response headers/body prefix, or network error to `console.warn`/`console.error`.

## Implemented behavior

`apps/web/e2e/redaction.mjs` now owns the marker, secret collection, and
redaction rules; `scrub-secrets.ts` calls the same module for loose files and
trace archives, so artifact and live-output behavior cannot drift. The
collector loads values from storage state plus secret-named environment
variables
(`SECRET`, `TOKEN`, `PASSWORD`, `PRIVATE`, credential/database URLs, and API
keys); short values remain excluded.

`apps/web/scripts/run-e2e-redacted.mjs` accepts `--` followed by the E2E
command, and `apps/web/package.json` invokes it for `test:e2e`. It:

1. collects environment and storage-state secrets before spawning the child;
2. spawns the child with stdin inherited and stdout/stderr piped separately;
3. feeds each pipe through an independent UTF-8-aware streaming redactor;
4. writes only redacted chunks to the corresponding parent stream; and
5. waits for both pipes to flush, then propagates the child's exit code or signal.
It forwards parent `SIGINT`/`SIGTERM` to the child and removes those handlers
before re-emitting a child signal, so cancellation cannot orphan the test
process or leave the wrapper running.

The streaming redactor processes complete newline-delimited records while
retaining an incomplete final record. On `end`, it flushes that record. For
very large lines, it emits one redaction marker and suppresses the rest of that
line rather than allowing unbounded memory or leaking a secret tail. The carry
covers arbitrary chunk splits, including splits inside a literal secret, JWT,
or `dvb_`/testing-token value. Redaction is replacement-only: status lines,
URLs without secrets, response bodies, and stack traces remain available for
diagnosis. Query values for `__clerk_*` parameters are always masked even when
their token format is unknown. Malformed storage state fails closed with a
generic startup error rather than exposing parser details.

The CI E2E step invokes the wrapper around the existing command. The wrapper
sets a nonzero exit status on spawn failure and preserves a child's nonzero
code; it never prints the child command or environment because those can
contain credentials.

## Red regression

`apps/web/e2e/stdout-redaction.unit.spec.ts` launches real child processes
through the implemented wrapper. The subprocess regressions cover collected
secrets and token-shaped values split across delayed stdout/stderr writes,
split UTF-8, unterminated output, oversized-line suppression, parent
`SIGINT`/`SIGTERM` forwarding without an orphan, env-file collection, generic
spawn failures, exit status, and benign diagnostics. The tests compare
booleans for secret presence and never include planted values in assertion
messages. `scrub-secrets.unit.spec.ts` continues to cover literal, JWT,
dev-browser, testing, Plaid, and malformed-state cases.

These are real subprocess regressions, not mocks of application or Clerk code;
they cover the implemented runner boundary and keep secret values out of test
failure output.

The isolated redaction suite passes all 16 tests, and the subprocess fixture has
also passed 20 repeated runs after the readiness-ordering fix. Lint, typecheck,
and whitespace checks pass for the implementation worktree.

The isolated correction tests and static checks use no credentials, production
requests, or live financial data. Full credentialed Clerk plus Plaid Sandbox
workflow validation remains required for the E2E definition of done and is
pending separately; production requests remain out of scope. The full API suite
passes 388 tests across 29 files with one worker. The first complete browser run
passed 88 tests; the final 89-test run includes the additional JSON compatibility
regression and remains pending at this commit. Multi-line environment secrets
and quoted JSON URLs each had an observed failing regression before correction.
