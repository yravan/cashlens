# 10.3 Test-log redaction

Scope: prevent Clerk testing and other E2E child-process secrets from reaching
live CI stdout or stderr. Artifact scrubbing remains in place. This change does
not alter application behavior, authentication, test assertions, or provider
requests.

## Observed leak

`@clerk/testing@2.2.22` installs a Playwright route handler that appends the
testing token to the FAPI URL. On a terminal FAPI failure it writes
`e.request().url()` to `console.warn`; the network-error path writes the same
URL to `console.warn` and may also call `console.error`. The status path appends
response headers and up to 500 characters of response body. Playwright forwards
those messages to the runner process, while `e2e/scrub-secrets.ts` only rewrites
files after the run. A public CI log can therefore contain a live dev-browser
or testing token even when uploaded artifacts are clean.

## Prior art and constraints

- Node `child_process.spawn` provides the process boundary and exposes exit,
  signal, stdout, stderr, and spawn-error events.
- Node `StringDecoder` preserves UTF-8 characters split across stream chunks.
- Node `Transform`/stream backpressure keeps the sanitizer from buffering the
  entire test run.
- Playwright's CLI is the existing E2E entry point and must remain observable
  through both output streams.
- Playwright reporters use stdout/stderr for diagnostics; the wrapper must not
  change test exit status or discard non-secret output.
- `@clerk/testing`'s `setupClerkTestingToken` route is the concrete producer of
  the leaked URL and is read locally from the pinned package.
- `e2e/scrub-secrets.ts` already defines the marker, collected secret values,
  and token-shaped patterns used for artifact cleanup.
- `e2e/scrub-secrets.unit.spec.ts` proves literal, JWT, dev-browser, testing,
  and Plaid token patterns in files and trace archives.
- `.github/workflows/ci.yml` currently runs `pnpm test:e2e` directly and only
  gates artifact upload on the post-run `.scrubbed` marker.
- GitHub Actions makes workflow stdout public to anyone with repository access,
  so post-run artifact cleanup cannot mitigate a live-log leak.

## Proposed implementation

Extract the pure marker, secret collection, and redaction rules from
`scrub-secrets.ts` into a small shared module. Keep the archive/file scrubber
calling that module so artifact and live-output behavior cannot drift.

Add a Node wrapper that accepts `--` followed by the E2E command. It should:

1. collect environment and storage-state secrets before spawning the child;
2. spawn the child with stdin inherited and stdout/stderr piped separately;
3. feed each pipe through an independent UTF-8-aware streaming redactor;
4. write only redacted chunks to the corresponding parent stream; and
5. wait for both pipes to flush, then propagate the child's exit code or signal.

The streaming redactor should process complete newline-delimited records while
retaining an incomplete final record. On `end`, it must flush that record. For
very large lines, use a bounded carry window and continue redacting known
literal values and token-shaped prefixes rather than allowing unbounded memory.
The carry must cover arbitrary chunk splits, including splits inside a literal
secret, JWT, or `dvb_`/testing-token value. Redaction is replacement-only:
status lines, URLs without secrets, response bodies, and stack traces remain
available for diagnosis.

The CI E2E step should invoke the wrapper around the existing command. The
wrapper must set a nonzero exit status on spawn failure and preserve a child's
nonzero code; it must never print the child command or environment because
those can contain credentials.

## Red regression

`apps/web/e2e/stdout-redaction.unit.spec.ts` launches a real child process
through the planned wrapper. The child writes a collected secret and a
token-shaped value split across delayed stdout/stderr writes, preserves benign
diagnostics, and exits with code 23. The test compares booleans for secret
presence and never includes either planted value in assertion messages.

This test is intentionally red on this design-only branch because the wrapper
does not exist yet. It is a subprocess regression, not a mock of application or
Clerk code; it becomes green only when the CI runner boundary is implemented.

Credentialed Clerk/Playwright runs, provider requests, and network access are
out of scope for this correction.
