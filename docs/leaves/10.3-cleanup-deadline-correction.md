# 10.3 cleanup re-authentication deadline correction

## Scope

Give the real-provider browser regression `cleanup re-authenticates after a
signed-out browser redirect` enough test-level time to complete its existing
workflow. This correction changes no application runtime, provider behavior,
cleanup helper, or functional assertion.

## Evidence

The scrubbed trace from the isolated calendar PR96 run at
`/Users/yajvanravan/cashlens-wt/6.4.2-calendar-overflow/apps/web/test-results`
showed the first Clerk sign-in ending at 8.2s, the real Plaid exchange at
21.1s, `/accounts` at 27.8s, and the user-menu interaction still running when
the default 30s test deadline expired. The failure was `Test timeout of 30000ms
exceeded`, not `session_exists`; the registered `afterEach` cleanup succeeded
and the database credential count was 0. The isolated full run recorded 120
passes and one unrelated failure over 7.8 minutes.

## Reuse and rationale

| Evidence | Decision |
|---|---|
| Playwright's [timeout guidance](https://playwright.dev/docs/test-timeouts) | Keep the timeout scoped to this test with `test.setTimeout(...)`; Playwright documents 30,000ms as the default and includes test setup and the test body in that budget. |
| `apps/web/e2e/connections.signed-in.spec.ts` `teardown removes an exchanged Item...` and `opening Accounts retries an aged failed-connect cleanup` | Reuse the existing 120,000ms real-provider connect/cleanup budget; the longer `management arc` remains 180,000ms. |
| `apps/web/e2e/plaid.signed-in.spec.ts` `a sandbox public token exchanged...` and `a backfill that never got driven...` | Confirm 120,000ms is the established budget for real Sandbox exchange/backfill workflows; do not change the suite-wide config or assertion deadlines. |

The correction sets this signed-out re-authentication workflow to 120,000ms.
That is the smallest existing real-provider workflow budget, already used by
the two connection-management cases above and the two Plaid Sandbox cases,
that leaves room for both Clerk sign-ins, the real exchange,
navigation/sign-out, and the provider-first cleanup retry. It is a bounded
workflow deadline, not an arbitrary retry or assertion timeout. All functional
assertions remain unchanged.

## Validation boundary

No E2E run is included in this correction; the parent validation owns the
provider slot. Static validation may lint or typecheck the changed test with
the repository's existing dependencies. Full green status requires a fresh
E2E rerun; the evidence above is not a passing rerun.
