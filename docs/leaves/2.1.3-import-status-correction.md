# 2.1.3 Import completion feedback

Scope: correct the connect flow's import message. No ingestion, storage, provider
scope, or sync-trigger changes.

The browser accumulated `step.added` from its own polling responses and displayed
that sum as the completed import total. A verified webhook or another browser
can commit rows between those requests. The sync engine correctly reports zero
new rows to a later caller, but the UI then understates the available history.

For example, a browser that inserts four rows before a webhook imports the rest
must not announce that only four transactions were imported. The existing
transaction-history count remains the authoritative ledger total.

Show import progress without a row count, and report completion only when
`pollSync` observes both a drained run and completed historical update. Preserve
the existing still-importing and interrupted messages.

## Provider and framework contracts

- [Plaid sync integration](https://plaid.com/docs/transactions/sync-migration/):
  cursor-based responses represent changes since a cursor, not the ledger total.
- [Plaid Transactions](https://plaid.com/docs/transactions/): initial and
  historical updates arrive asynchronously through sync and webhooks.
- The installed Next.js `useRouter` reference specifies that `router.refresh()`
  preserves unaffected client state. Refreshing server data therefore does not
  make a browser-local accumulated counter authoritative.

Existing API coverage exercises concurrent sync, cursor protection, and webhook
ingestion. This correction removes the inaccurate client counter and introduces
no new data-access surface.
