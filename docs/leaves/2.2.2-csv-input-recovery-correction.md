# 2.2.2 CSV Input Recovery Correction

Status: correction for the approved 2.2.2 design.

The import identity contract remains the approved date + minor amount + normalized description + occurrence within the submitted file (`2.2.2-statement-import-design.md`, sections 2 and “Dedup and idempotency rule”). The oversized-file message now tells the person to split one export only at complete date boundaries, keeping every row for a date in one request. A single date over the limit cannot be imported yet; the message explicitly says not to split that date across files, because separate uploads do not share occurrence state.

The browser normalizes redundant leading zeroes before posting rows. This keeps a visually valid CSV amount within the server’s 32-character wire limit without changing `amountMinor` or `source_id` identity. The focused unit regression proves both a long leading-zero amount and signed ordinary zero-padding; existing same-file occurrence and re-upload tests remain unchanged.
