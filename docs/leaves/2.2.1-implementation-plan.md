# Manual Transactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a signed-in person create, fully correct, and permanently delete their own posted manual ledger transactions from `/transactions`, without changing provider-authored rows or account balances.

**Architecture:** Reuse the canonical `transactions` table. A pure boundary module validates the closed request and converts unsigned decimal strings exactly; an RLS-scoped DAL derives identity, resolves account currency and category authority, performs each atomic mutation, then repairs transfer matches after commit. Three guarded POST handlers expose the DAL, while one focused client island adds create/edit/delete controls to the existing server-rendered history page.

**Tech Stack:** pnpm workspace; Next.js 16 App Router; React 19; TypeScript; Tailwind CSS v4; Clerk; PostgreSQL 16; Drizzle ORM; Vitest against real PostgreSQL; Playwright 1.62 against a production build and real Clerk development users.

**Spec:** `docs/leaves/2.2.1-manual-transactions-design.md`

## Global Constraints

- Scope is exactly `2.2.1 Manual transactions [P1] — Add, edit, and delete transactions by hand — cash spending and anything no feed can see.`
- Any existing owned Plaid, manual, or import account may receive a manual row.
- Edit may atomically reassign account and denomination; there is no FX conversion.
- Manual mutations never write `account_balances`.
- Identity comes only from Clerk through `requireUser()`; request bodies never carry a user ID.
- Every user-data mutation enters `withRequestScope()` and keeps explicit `user_id` predicates in addition to forced RLS.
- Input is closed and bounded before SQL. Malformed string IDs reach resource resolution and return resource-class 404s; wrong JSON types return `invalid_request`.
- Currency comes only from the selected owned account. Submitted money remains a string until exact minor-unit conversion and never passes through whole-value floating-point parsing.
- Manual rows are always `source='manual'`, `source_id=NULL`, and `status='posted'`; those fields are not caller-controlled or editable.
- Unknown and cross-user IDs are byte-identical within each resource class. Plaid/import edit or delete targets are indistinguishable from missing manual targets.
- `guardPost()` runs before JSON parsing on every route.
- Financial text, amount, account/category data, request bodies, tokens, raw errors, and secrets are never logged. Matcher failures log only `event`, `operation`, and sanitized `errorClass`.
- Add only `GRANT UPDATE ("account_id") ON TABLE "transactions" TO "cashlens_app"`; add no table, schema object, dependency, secret, provider scope, upload, webhook, external request, or background job.
- The Transactions page preserves its applied-query form key and all existing provider-row category behavior.
- Each meaningful test is observed RED before implementation. Critical behaviors are then deliberately broken one at a time, observed RED, and restored byte-for-byte.
- Commit messages end with `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
- Never merge the PR. The founder reviews and merges it.

## Shared interfaces

`apps/web/lib/ledger/minor-units.ts` produces:

```ts
export function parseMajorUnits(value: string, currency: string): number | null;
export function formatMajorUnits(minorUnits: number, currency: string): string;
```

`parseMajorUnits` validates an unsigned plain-decimal string, rejects malformed syntax, excess precision, and unsafe minor integers, and returns zero when the exact value is zero. It composes `BigInt(whole + paddedFraction)`, compares against `BigInt(Number.MAX_SAFE_INTEGER)`, then converts to `number`. `formatMajorUnits` requires a non-negative safe integer and trims trailing fractional zeroes.

```ts
export function parseMajorUnits(value: string, currency: string): number | null {
  if (!/^\d+(\.\d+)?$/.test(value)) return null;
  const [whole, fraction = ""] = value.split(".");
  const digits = currencyExponent(currency);
  if (fraction.length > digits) return null;
  const minor = BigInt(`${whole}${fraction.padEnd(digits, "0")}`);
  if (minor > BigInt(Number.MAX_SAFE_INTEGER)) return null;
  return Number(minor);
}

export function formatMajorUnits(minorUnits: number, currency: string): string {
  if (!Number.isSafeInteger(minorUnits) || minorUnits < 0) {
    throw new Error("minor units must be a non-negative safe integer");
  }
  const digits = currencyExponent(currency);
  const units = String(minorUnits).padStart(digits + 1, "0");
  if (digits === 0) return units;
  const point = units.length - digits;
  const fraction = units.slice(point).replace(/0+$/, "");
  return fraction ? `${units.slice(0, point)}.${fraction}` : units.slice(0, point);
}
```

The callers retain their own regex gate, so `BigInt` never sees malformed input.
