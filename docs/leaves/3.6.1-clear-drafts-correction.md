# 3.6.1 Clear unsubmitted filter drafts

Scope: the existing Transactions Clear action must discard draft filters as well as
remove applied URL filters. No query, ledger, category, or authorization changes.

Live reproduction: open the unfiltered ledger, edit fields without pressing Apply,
then Clear. The URL stays unfiltered, but the edited values remain and the next Apply
submits them. The existing query key cannot reset inputs when the URL does not change.

The [original history design](3.6.1-transaction-history-design.md) makes the URL the
source of applied filters. Keep its key-based remount for changed queries, and use a
native form reset on Clear's Next.js `onNavigate` callback for draft values. Unlike
`onClick`, `onNavigate` does not fire for modifier-clicks opening a new tab. The
installed Next.js Link reference documents this distinction. A DOM ref is the only
new client state; there is no mirrored filter state or effect.

The real-browser regression was observed red before the fix: Search retained `acme`
after Clear on `/transactions`. It edits all eight filters, asserts all are cleared,
then applies and verifies the exact synthetic ledger order and count. Existing tests
retain applied-filter Clear, reload, pagination/Back, invalid queries, mobile layout,
and user isolation coverage.

Tests use an isolated localhost database and synthetic fixture data. Temporary test
port overrides are restored before commit. No production data or credentials appear
in this correction.
