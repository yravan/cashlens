# 2.2.2 CSV Direction Correction

Scope: preserve explicitly mapped money-out/money-in direction when switching
from a signed amount column. No identity, import endpoint, database, matching,
or category changes.

## Prior art and decision

This correction reuses the leaf's [30-source survey](./2.2.2-prior-art.md) and
[approved importer design](./2.2.2-statement-import-design.md). The relevant
adopted patterns are explicit signed-column conventions (Actual/Maybe), named
outflow/inflow columns (YNAB/GnuCash), and an exact live preview (Lunch Money).
Papa Parse, amount parsing, and all existing server validation remain unchanged.
No new dependencies or merchant heuristics are introduced.

The original design allowed a global flip. Its shipped checkbox says "Money
out is positive in this file", which is also true for ordinary positive Debit
columns. Applying that setting after mapping Debit as money out reverses the
user's explicit direction. A checked flag also persists when switching layouts.

The sign checkbox now applies only to a single signed amount column and is
hidden for split columns. The pure interpreter likewise ignores the flag for
split input, so a retained UI setting cannot reverse explicitly mapped columns.
To correct swapped debit/credit mappings, change the named column selections.
The signed-column flag is preserved when switching back; its behavior is unchanged.

## Reproduction and evidence

Actual input: purchase 12.50 in Debit, refund 9.75 in Credit. A signed column uses
the opposite convention and requires the checkbox. Switch to explicit Debit/
Credit columns without unchecking it.

- Unchanged runtime, focused unit suite: **2 failed, 87 passed**. Expected
  amounts `[-1250, 975]`; actual `[1250, -975]` in minor units.
- Unchanged runtime, actual browser: the same preview comparison failed after
  the layout switch. The preceding signed-column comparison passed.
- Corrected runtime, focused unit suite: **89 passed / 3.78s**.
- Corrected runtime, full API/unit suite: **739 passed / 45 files / 13.06s**.
- Lint and typecheck pass; the browser runner's production build succeeds.
- The browser regression also verifies checkbox absence, successful import,
  exact persisted amounts, and the resulting account balance. It passes on the
  corrected runtime (1.5s), alongside ordinary import/replay/delete/isolation and
  mobile import cases. The full run has 116 passes and five failures involving
  authentication/sign-in; it is not a green full-suite claim. Another concurrent
  worktree was observed using the same fixed test ports; isolated reruns remain
  required before attributing those failures to runtime behavior.
- Isolated full browser rerun: **121 passed / 9.5m**, including the real Plaid
  sandbox lifecycle, CSV persistence/balance, and cross-user isolation. Local
  ports 3310/3311/3399 and dedicated development users prevented collisions with
  the other worktree. Temporary overrides were restored; no product auth changes
  or weakened assertions were needed. This does not prove the cause of every
  earlier authentication failure.
- Independent post-PR Luna review of `a5b1b47`: no blockers or worthwhile
  simplifications; split-to-signed UI return coverage is a low-risk test gap.

An existing assertion expected flipped split-column output; it encoded the
contradictory contract and now asserts that the selected direction wins. This
is an intentional behavior correction, not weakening an assertion for green CI.

## Security and boundaries

No new server surface, external transmission, schema, or privileges. Existing
import ownership, cross-user isolation, body caps, exact decimal conversion,
and idempotency tests continue to apply. New fixture values are synthetic.
No production transaction was imported or changed by this correction.

The broader audit separately tracks split-file occurrence identity, overly
padded amount strings, and numeric aggregate limits; they are not silently
claimed fixed here.
